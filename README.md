# AI Support Copilot для amoCRM

Сервис принимает обращение клиента, сверяется с базой знаний и за **один запрос к Claude** возвращает два блока:

1. **💬 Вежливый ответ клиенту.** Первые слова появляются сразу: ответ передаётся по мере генерации (стриминг).
2. **💡 Подсказку по допродаже для менеджера.** В ней товар, почему он подходит именно этому клиенту и готовая фраза. Подсказка учитывает сделку в amoCRM (этап, покупки, теги) и то, что менеджер уже писал в диалоге.

Демо-компания — интернет-магазин кофемашин «Бариста Дома». Она вымышленная, база знаний лежит в `kb/knowledge.md`.

## Почему это быстрее типового решения

| Что | Типовое решение | Здесь |
|---|---|---|
| Поиск по базе знаний | эмбеддинги + векторная БД + отдельный сетевой запрос | база короткая, поэтому целиком лежит в системном промпте с **prompt caching**. Повторно она читается из кэша API: быстрее и в 10–20 раз дешевле обычных входных токенов |
| Запросы к LLM | 2 (ответ и допродажа) | **1 запрос**, строгая JSON-схема (structured outputs) с обоими блоками. Формат гарантирован API: невалидного JSON не бывает |
| Ожидание ответа | пустой экран до конца генерации | **стриминг**: поле `reply` стоит в схеме первым, и потоковый JSON-парсер (`app/jsonstream.py`) отдаёт текст клиенту, пока модель дописывает подсказку |
| Холодный старт | первый запрос медленный | **прогрев кэша** при старте и поддержание кэша тёплым при простое |
| Повторяющиеся вопросы | каждый раз запрос к LLM | **локальный LRU-кэш**: ответ за ~1 мс и $0 |
| Сбой API | ошибка у клиента | **резервный движок без ИИ**: ответ по базе и правилам допродаж. При отказе классификатора безопасности модель сама переключается на резервную (`fallbacks: "default"`) |
| Галлюцинации в допродажах | как повезёт | **детерминированная проверка**: только товары из правил базы и никогда то, что у клиента уже есть |
| Зависимости | LangChain, векторная БД, Streamlit… | **3 пакета**: `anthropic`, `fastapi`, `uvicorn` (uvloop + httptools) |
| Интерфейс | фреймворк и сборка | один HTML-файл без сборки |

Утверждения про скорость проверяются замером: `bench.py` гоняет оба подхода на одних и тех же обращениях (см. ниже).

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env          # впишите ANTHROPIC_API_KEY
uvicorn app.main:app --port 8000   # uvloop и httptools подхватываются автоматически (кроме Windows)
# откройте http://localhost:8000
```

Или в Docker:

```bash
docker build -t ai-copilot .
docker run --rm -p 8000:8000 --env-file .env ai-copilot
```

Без `ANTHROPIC_API_KEY` сервис тоже запускается, но в **резервном режиме**: отвечает по базе знаний без ИИ. Так удобно проверить интеграцию и интерфейс.

## Демо-окно

Интерфейс сделан в стиле карточки сделки CRM:

- **слева** — сделки: новый клиент, клиент с кофемашиной, офис, постоянный клиент с подпиской;
- **по центру** — чат. Вы пишете от лица клиента (или нажимаете готовый пример), менеджер отправляет ответ одной кнопкой;
- **справа** — панель ИИ-помощника:
  - скорость (до первого слова и до готовности обоих блоков), токены из кэша, цена запроса;
  - черновик ответа клиенту: его можно отредактировать, есть режим автоответа;
  - подсказка по допродаже;
  - анализ обращения: тональность, найден ли ответ в базе, нужен ли менеджер, на какие разделы базы опирается ответ.

Подсказка зависит от контекста. На вопрос «кофе закончился» клиенту без подписки предлагается подписка, а клиенту, у которого она уже есть, — нет. То, что менеджер уже предлагал в диалоге, повторно не предлагается.

## Подключение amoCRM

1. В amoCRM создайте внешнюю интеграцию и получите **долгосрочный токен**. Задайте `AMO_SUBDOMAIN` (например, `mycompany` для `mycompany.amocrm.ru`) и `AMO_TOKEN`.
2. Опубликуйте сервис по HTTPS. Для демо подойдёт туннель `cloudflared tunnel --url http://localhost:8000`.
3. В amoCRM → Настройки → Вебхуки добавьте URL `https://<ваш-домен>/webhook/amocrm?secret=<AMO_WEBHOOK_SECRET>` и отметьте события входящих и исходящих сообщений.

Как это работает:

- Входящее сообщение клиента → сервис сразу отвечает amoCRM `200` и в фоне:
  1. читает сделку через API v4 (название, контакт, бюджет, теги);
  2. генерирует оба блока;
  3. добавляет в сделку **примечание** с черновиком ответа и подсказкой по допродаже.
- Исходящие сообщения менеджера сохраняются в историю диалога. Так подсказка учитывает, что менеджер уже говорил и предлагал.
- Покупки клиента передаются через **теги сделки**, например `кофемашина`, `подписка`, `гарантия+`. Их сверяют с полями `нужно` и `исключить` в правилах допродаж.

Без `AMO_*` вебхук тоже работает: примечание пишется в лог, а контекст берётся из демо-сделок.

## API

| Метод | Что делает |
|---|---|
| `POST /api/ask` | Стриминг (SSE). Вход: `{"message", "deal_id"}` или `{"message", "deal": {...}, "history": [...]}`. События: `meta` → `delta`… (текст ответа) → `result` (оба блока + метрики). Если ИИ сломался посреди ответа, приходит `reset`, а затем ответ из резервного движка |
| `POST /api/answer` | То же одним JSON-ответом |
| `POST /webhook/amocrm` | Вебхук сообщений amoCRM |
| `GET /api/config`, `/api/stats`, `/healthz` | Режим, модель, счётчики |

Формат результата:

```json
{
  "reply": "Игорь, здравствуйте! …",
  "found_in_kb": true, "escalate": false, "sentiment": "neutral",
  "kb_refs": ["Кофе в зёрнах"],
  "upsell": {"rule_id": "beans_subscription", "product": "Подписка «Свежая обжарка» — …",
             "reason": "…", "script": "…", "priority": "high"}
}
```

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ Claude API; без него включается резервный режим |
| `LLM_MODEL` | `claude-opus-5-5` | модель. Для сравнения скорости: `claude-sonnet-5-5`, `claude-haiku-4-5` |
| `LLM_EFFORT` | `low` | глубина рассуждений (`low`…`max`). Для чата `low` даёт минимальную задержку |
| `PROMPT_CACHE_TTL` | `1h` | время жизни кэша базы знаний на стороне API (`1h` или `5m`) |
| `PROMPT_PREWARM` | `true` | прогревать кэш при старте и при простое |
| `ANSWER_CACHE_TTL` / `ANSWER_CACHE_SIZE` | `600` / `512` | локальный кэш ответов на типовые вопросы |
| `KB_PATH` | `kb/knowledge.md` | файл базы знаний |
| `AMO_SUBDOMAIN`, `AMO_TOKEN`, `AMO_WEBHOOK_SECRET` | — | интеграция с amoCRM |

Промпт с базой занимает около 4 тыс. токенов. Этого хватает для кэширования на Opus 5.5 и Sonnet 5.5 (минимум 512 токенов), а у Haiku 4.5 минимум 4096 токенов, так что короткая база там может не закэшироваться. Проверить можно по метрике «токенов из кэша» в интерфейсе.

## Замеры и качество

```bash
python bench.py --runs 2                         # оба подхода, модель из LLM_MODEL
python bench.py --runs 2 --model claude-sonnet-5-5
```

Скрипт прогоняет 12 обращений из `tests/cases.json` двумя способами:

- **ours** — как работает сервис;
- **naive** — типичная сборка: 2 последовательных запроса без стриминга и без кэша.

Он считает время до первого слова и до полного ответа (медиана и 95-й процентиль), стоимость 1000 обращений и качество: верная ли допродажа, найден ли нужный раздел базы, правильно ли решено, звать ли менеджера, нет ли запрещённых обещаний. Таблица сохраняется в `bench/results.md`, её удобно показать в видео.

Автотесты (Claude в них подменяется фейковым стримом, ключ не нужен):

```bash
pip install -r requirements-dev.txt && pytest -q
```

## Структура

```
app/
  main.py        HTTP: демо-окно, SSE API, вебхук amoCRM
  service.py     конвейер: локальный кэш → Claude → резервный движок; метрики; прогрев кэша
  llm.py         запрос к Claude: JSON-схема, стриминг, prompt caching, fallbacks
  jsonstream.py  потоковый парсер поля reply из недописанного JSON
  prompt.py      системный промпт и схема ответа
  kb.py          загрузка базы знаний из Markdown
  offline.py     резервный движок без ИИ
  amocrm.py      клиент amoCRM API v4, разбор вебхуков, демо-сделки
kb/knowledge.md  база знаний и правила допродаж: редактируется без программиста
static/index.html демо-интерфейс
bench.py         бенчмарк против типичного решения
tests/           автотесты и тестовые обращения
```
